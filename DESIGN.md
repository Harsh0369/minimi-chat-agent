# minimi chat agent

Architecture proposal • 10 November 2026 • Implementation and measurements pending

**Purpose.** Build a conversational agent that remembers previous questions and their dates, searches the web, and rechecks earlier answers. Optimize answer quality, time awareness, responsiveness, and explainable decisions. A missing memory or uncertain source produces a focused clarification or a qualified answer.

**Execution.** TypeScript on Node 24 LTS, Express 5 with Zod boundary validation, and a small React/Vite chat interface run through one `npm run dev` command. One orchestrator assembles history and lets the model answer, clarify, or call the sole exposed tool, `web_search`. Tavily Search supplies source content. Independent searches run with bounded concurrency. The application owns authorization, deadlines, budgets, persistence, and citation IDs. A model adapter permits evaluation of eligible free-tier Gemini models and other configured providers; choose the final provider and model through task evaluations and document the privacy trade-off.

**Memory.** SQLite through `better-sqlite3` stores original messages, turn states, source excerpts, and claim observations. A worker owns synchronous database access. Retrieve exact dates through indexes and topics through FTS5; add selective embeddings over episodes only if measured paraphrase recall needs them. Fuse retrieval ranks where the additional index helps, expand selected hits to their surrounding turns, and assemble context within a token budget. Preserve originals as evidence; summaries and embeddings remain rebuildable indexes. Lexical/date retrieval remains available during provider failures. Conversation ownership scopes every retrieval.

**Time and change.** Preserve UTC message time, user timezone, source publication time, observation time, and any evidenced effective date separately. Resolve relative dates against an injected clock. Recover the earlier shortlist before researching its members. Compare equivalent product, plan, currency, billing period, and unit. Report an observed difference, matching observations, conflicting evidence, or insufficient evidence. A difference between observations alone cannot establish its effective date. Correct earlier mistakes explicitly and retain the historical answer.

**Evidence and trust.** Search primary pricing pages and announcements, retaining excerpts and retrieval timestamps. Bypass application caches for explicit rechecks and record provider freshness limitations. Draft material claims against server-issued source IDs. Validate IDs, quotations, and comparable numeric fields in code; use an additional evidence-only check for change claims and conflicts. Unsupported claims are narrowed or withheld. Source text remains untrusted, tool arguments are bounded, and safe rendering accepts only validated citation links. These controls reduce errors; semantic support still requires evaluation.

**Reliability.** Persist a turn before external calls. Idempotency keys prevent duplicate answers, one active turn per conversation preserves order, and final answers commit atomically with evidence. Apply request limits, bounded queues, provider concurrency caps, cancellation, deadlines, and capped jittered retries at one layer. Recover interrupted turns after restart. Stream progress while verifying evidence. Persist completed answers before delivery. Keep secrets server-side and exclude private data from normal logs.

**Trade-offs and evaluation.** Express fits the small API and the author's experience; Fastify offers stronger integrated schemas. SQLite simplifies local setup; Postgres becomes appropriate for multiple application replicas. A dedicated vector service adds operational cost at this scale. Multi-agent delegation, always-on critics, and an orchestration framework add calls and state to a short, single-tool workflow. Compare lexical-only and hybrid retrieval, then measure recall, supported claims, justified abstention, latency, and cost on fixed-clock conversations and held-out live questions. Test failures and clean-clone startup. Initial sources include [LongMemEval](https://xiaowu0162.github.io/long-mem-eval/), [Anthropic](https://www.anthropic.com/research/building-effective-agents), and [AWS](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/).
