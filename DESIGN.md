# Design

**Goal.** Answer ordinary questions quickly, remember what the user asked and when, and recheck time-sensitive answers against the web. The agent has one external tool, `web_search`. It runs with `npm install` and `npm run dev` on Node 24. Required keys are listed in `.env.example`.

**Flow.** Express validates and records a turn; a worker owns SQLite. The active chat is primary. A tool-free model call classifies context only when a question may need past interaction or clock facts; a self-contained first question skips that call. Clock-only and memory-only answers cannot call web search. Exact-day and FTS5 queries retrieve original messages; optional Gemini embeddings are stored in SQLite with bounded backfill and lexical fallback. A byte-bounded context pack favors recent chat and exact-date records. For multi-item rechecks, a fast parser or validated model extraction recovers the historical list; the search plan checks each item and aspect, using likely vendor domains to focus pricing searches. LangGraph runs bounded reasoning, Tavily web search, citation checking, and one repair. Search failures are isolated per query. At most twelve searches run per answer, five in flight. Only returned source IDs become citations; the final answer and cited snapshots commit together. Output streams through NDJSON. Failed turns are retryable.

**Time, location and evidence.** Exact calendar dates are resolved in the user's IANA timezone before querying stored UTC timestamps. The router can request validated IANA zones; Node computes local date and time facts before the answer model runs. Timezone never supplies a city: unspecified weather, traffic and nearby questions ask for a location, while broad prices may search a labeled country-level hint. Explicit places win. A missing dated memory produces a direct “I can't find it” response. Earlier cited source snapshots are retrieved with the old answer. A sourced answer gets a separate evidence review; multi-item rechecks use a typed finding for each item and aspect. Citation IDs, vendor/product fit, monetary figures, and dated changes are checked against retrieved excerpts. A current observation alone cannot prove a change. These checks reduce unsupported claims but cannot establish that every sentence is entailed by a full page.

**Reliability.** One active turn is allowed per conversation and three globally, or one with Groq's tighter quota. A turn service owns admission, cancellation and persistence. Disconnects abort generation, partial text never enters memory, and retries reuse the original question. A 45-second deadline, bounded database queue, input limits, local-origin enforcement, owner-scoped reads, and server-only keys constrain risk. Embeddings and their source messages cascade-delete together. Browser sessions are anonymous local workspaces; public hosting and cross-device sync would need sign-in, spending controls, and shared storage.

**Choices.** Express and SQLite keep setup to one process. FTS5 and exact dates remain the baseline; optional vectors improve paraphrase recall without a separate vector service. The graph is request-local because a second checkpoint database would duplicate private conversation state and deletion work. Gemini stays the default through its native adapter, which preserves opaque tool-call signatures. OpenAI and Groq use LangChain model integrations behind the same interface; Groq gets smaller context and one active turn to respect its lower token quota. Tavily remains the only model-visible external tool. No multi-agent workflow or model picker is needed.

Add selective full-page extraction within `web_search` for claims that snippets cannot settle, and compare its extra latency and search credits with answer quality.
