# Design

**Goal.** Answer ordinary questions quickly, recall what the user asked and when, and recheck time-sensitive claims. The model has one external tool: `web_search`. `npm install` and `npm run dev` start the TypeScript/Node app; `.env.example` lists its keys.

**Request path.** Express validates a turn and stores it through a SQLite worker. The active chat is primary. A tool-free model call chooses thread or workspace context only when history or time may matter; a self-contained first question skips it. Exact-day lookup and FTS5 retrieve original messages. Optional Gemini embeddings in SQLite improve paraphrase recall; indexing runs after turns, while lexical recall remains available. A byte budget favors the active chat and exact-day records. Clock-only and memory-only answers cannot search the web.

**Research.** A bounded LangGraph loop lets the model request Tavily searches, then drafts, checks citations, and repairs once if needed. Multi-item rechecks recover the earlier shortlist, search each item and requested aspect, and keep failed searches marked unverified. Independent searches run five at a time, with twelve at most per answer. Results are ranked before provider context limits; likely vendor domains and pricing or release pages receive priority. The model sees excerpts, not full pages. The final cited source snapshots commit with the answer, so a later recheck can compare old and current evidence.

**Time and evidence.** Node resolves dates from stored UTC timestamps in the user's IANA timezone. The router may request other valid zones; Node computes those clock facts. A timezone is not a city, so location-specific questions without a place ask for one. The answer workflow prefers official sources, checks cited IDs and monetary figures, and separates current observations from proven changes. A price change needs comparable old and current tiers, currency, units and terms; a release needs a date after the reference point. These checks reduce unsupported claims but cannot prove every sentence from an excerpt.

**Reliability and scope.** Turns are idempotent, cancellable and capped at 45 seconds. Disconnects abort work; partial text never enters memory. Bounded database work, local-origin checks, owner-scoped reads and server-only keys constrain risk. Anonymous sessions suit local evaluation; public multi-user hosting or cross-device sync would require sign-in, spending controls and shared storage. Gemini is the default. OpenAI and Groq sit behind the same provider interface, with tighter context and concurrency limits for Groq. I kept SQLite instead of a separate vector or graph checkpoint database, and a bounded single-agent workflow instead of multiple agents, to keep setup and state inspectable.

**With another week.** Run held-out dated-recall and comparison conversations on each provider; review every material citation and measure latency and rate-limit failures. Add selective full-page extraction inside `web_search` when excerpts cannot settle a claim, then measure its cost. `docs/EVALUATION.md` records observations, not parity with leading agents.
